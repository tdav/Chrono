# Вход через Google и синхронизация с Google Календарём: дизайн

Дата: 2026-10-20. Статус: согласован пользователем.

Второй из трёх проектов (порядок согласован: «Распорядок» → этот → трекер цикла). Строится поверх ветки `feature/daily-schedule` (проект «Распорядок», спецификация [2026-10-20-daily-schedule-design.md](2026-10-20-daily-schedule-design.md)): там запись Chrono — одна сущность «будильник/дело» с длительностью, иконкой, уровнем оповещения (`None`/`Notify`/`Ring`), повтором и датой начала.

## 1. Зачем

Пользователь хочет, чтобы расписание Chrono жило в его Google Календаре: события, поставленные с компьютера, появлялись на телефоне и звонили, а после установки Chrono на новый телефон всё расписание подтягивалось из Google.

## 2. Решения пользователя

| Вопрос | Решение |
|---|---|
| Событие, поставленное в Google | Появляется в ленте «Распорядка» и во вкладке «Будильники» (звонит) |
| Напоминание Google у события (например, «за 30 мин») | Звонить **оба раза**: по напоминанию и в момент начала |
| Запись «Один раз и удалить» после срабатывания | Удаляется и из Chrono, и из Google *(решение пользователя 2026-10-20, заменило прежнее «остаётся в Google как история»)* |
| Какие календари | Только собственный календарь **«Chrono»**, который приложение создаёт само; остальные календари не трогаются |
| Установка на новый телефон | После входа все события календаря «Chrono» становятся записями |
| Кто пользуется | Только пользователь и тестировщики; публикации в Google Play для всех пока нет |
| Поведение синхронизации целиком | Согласовано пересказом (раздел 4), включая догадки, помеченные там |
| Аккаунт для настройки Google Cloud и приёмки | **Личный аккаунт пользователя** — тестовые события приёмки попадут в его настоящий Google Календарь (в календарь «Chrono»); после приёмки — убрать тестовые события |
| Тесты | **Нужны**: unit-тесты (xUnit, `tests/Chrono.Tests`) на чистую логику — соответствие запись ↔ событие (повторы, пояса, весь день, неподдерживаемые повторы, прошедшие события), конфликты, очередь изменений, дополнительные звонки по напоминаниям; вход и обмен с Google — приёмка на эмуляторе |

## 3. Цели, не-цели, анти-цели

**Цели**
1. Кнопка «Войти через Google» и «Выйти» в «Настройках»; видно, под каким аккаунтом вошли.
2. Календарь «Chrono»: найти или создать при первом входе.
3. Двусторонняя синхронизация записей с событиями календаря «Chrono».
4. Первичная загрузка после входа на новом телефоне.
5. Звонок по напоминаниям Google в дополнение к звонку в момент начала.

**Не входит**
- Другие календари пользователя (рабочий, «Праздники», «Дни рождения»).
- Синхронизация отметок «сделано» (остаются на телефоне).
- Изменения отдельного повторения серии, сделанные в Google («только это событие») — см. 6.6.
- Публикация в Google Play для всех и прохождение проверки Google (verification).
- Свой сервер; вход на iOS проверяется только сборкой (Mac нет).
- Совместные календари, приглашения участников, видеовстречи.

**Анти-цели — провал, даже если «работает»**
- Будильник не звонит без интернета или из-за ошибки синхронизации. Звонок всегда ставится в самом телефоне; синхронизация — только источник данных.
- Chrono изменил или удалил что-то вне календаря «Chrono».
- Одно и то же событие задвоилось в ленте после синхронизации (дубли при повторной загрузке, при входе на втором телефоне, при одновременной правке).
- Пользователь молча вылетел из аккаунта и не знает, что синхронизация остановилась.

## 4. Поведение (согласовано)

- **Вход** — кнопка в «Настройках». *(догадка, согласована)* Без входа приложение работает как сейчас, только локально; синхронизация включается после входа. Выход — синхронизация останавливается, записи на телефоне остаются.
- **Календарь «Chrono»** — при первом входе ищется среди календарей, созданных приложением, если нет — создаётся.
- **Google → Chrono** — событие календаря «Chrono» становится записью: видно в ленте и во «Будильниках», звонит по напоминанию Google и в момент начала. *(догадка, согласована)* Изменение или удаление в Google так же меняет или удаляет запись в Chrono.
- **Chrono → Google** — любая новая или изменённая запись (включая повторы) попадает в календарь «Chrono»; удалённая в Chrono любым путём (вручную, «Стоп» у «Один раз и удалить», автоудаление после срабатывания) — удаляется и из Google. Без сети удаление ждёт в очереди.
- **Звонок не зависит от сети** *(догадка, согласована)* — будильники ставятся в телефоне; без сети всё звонит вовремя, синхронизация догоняет при открытии приложения, после каждой правки и периодически в фоне.
- **Отметки «сделано»** *(догадка, согласована)* — не синхронизируются.

## 5. Ограничения

- .NET MAUI 11 (`net11.0-android;net11.0-ios`), Android — основная платформа и приёмка на эмуляторе; iOS только компилируется.
- Хранение записей — JSON (`AlarmStore`), как сейчас; правило `AlarmService.Save` «время в будущем» не ослаблять.
- Токены внешних API — в `IMemoryCache`, срок жизни из `expires_in` с запасом, на 401 — удаление из кэша (глобальное правило пользователя).
- Приватные поля без `_`, без лишних private-помощников, комментарии и коммиты на русском (правила пользователя).
- Тесты — по решению пользователя (раздел 2).
- Вход в Google на эмуляторе выполняет **сам пользователь** (пароли агенты не вводят) — в плане это ручной шаг с паузой; создание событий с компьютера для проверки Google → Chrono — тоже шаг пользователя или через Calendar API с токеном приложения.
- ApplicationId Android — `com.chrono.alarm`.
- **Ветка-основа содержит открытые дефекты** приёмки «Распорядка» (падение при полноэкранном сигнале, потеря уведомлений `Notify` и др., журнал `.superpowers/sdd/2026-10-20-daily-schedule/progress.md`). Их исправление не входит в этот проект, но приёмка синхронизации на эмуляторе может на них наткнуться.

## 6. Решения по «как» (мои, пользователь отдал выбор мне)

### 6.1 Доступ к Google

- **Область доступа** — `https://www.googleapis.com/auth/calendar.app.created` («создавать вторичные календари и видеть, создавать, менять и удалять события в них»). Технически не даёт видеть другие календари — совпадает с решением «только Chrono». Плюс `openid email` — показать, под каким аккаунтом вошли.
- **Android** — Google Identity Services `AuthorizationClient` (пакет `Xamarin.GooglePlayServices.Auth` 122.0.0, привязка `play-services-auth` 22.0.0; совместим с net10.0-android36, для net11 — проверить первой задачей). Устаревший Google Sign-In не использовать. Без offline-доступа и без своего сервера: access token на ~1 ч, при истечении — повторный `authorize` без интерфейса, если доступ уже выдан; если нужен интерфейс (доступ отозван) — синхронизация останавливается и в «Настройках» появляется «Войти снова».
- **iOS** — `WebAuthenticator` MAUI с PKCE и iOS-клиентом OAuth; только сборка.
- **Проект Google Cloud** — тип аудитории External, **статус «В продакшене» без прохождения проверки** (мой выбор). Причина: в статусе «Тестирование» разрешение каждого тестировщика сгорает через 7 дней — пришлось бы входить каждую неделю, а фоновая синхронизация молча вставала бы. В продакшене без проверки: при входе показывается предупреждение «приложение не проверено» (нажать «Дополнительно» → «Перейти»), лимит — 100 пользователей за всю жизнь проекта.
- **Настройку Google Cloud** выполняю я через браузер пользователя (его просьба) в рамках первой задачи плана: проект, включение Calendar API, экран согласия, OAuth-клиент Android (пакет + SHA-1 отладочного ключа; для release-ключа — когда он появится), клиент iOS. Каждый шаг с принятием условий Google, вводом данных или изменением настроек аккаунта — с отдельным подтверждением пользователя в чате.

### 6.2 Соответствие записи и события

| Запись Chrono | Событие Google |
|---|---|
| `Label` (пусто → «Будильник») | `summary` |
| `At` + время суток | `start.dateTime` в поясе телефона (`start.timeZone` — IANA-имя пояса телефона) |
| `DurationMinutes` | `end = start + длительность` (0 → `end == start`) |
| `Repeat`: Daily / Weekly(`Days`) / Yearly | `recurrence`: `RRULE:FREQ=DAILY` / `FREQ=WEEKLY;BYDAY=…` / `FREQ=YEARLY` |
| `StartsOn` | дата `start` первого повторения |
| `None` / `OnceThenDelete` | событие без `recurrence` |
| `Alert`, `Icon`, `SoundId`, `SoundEnabled`, `VibrationEnabled`, признак `OnceThenDelete`, `Id` записи | `extendedProperties.private` (ключи `chronoId`, `alert`, `icon`, …) |
| — | `reminders` события Google → дополнительные звонки (6.4) |

- Связь записи и события — по id события Google, сохраняется в записи (новое поле); `chronoId` в событии — для сопоставления при первой загрузке на другом телефоне.
- **Событие, созданное в Google** (без `extendedProperties`): `Alert = Ring` (решение пользователя — «появляется в будильниках»), иконка `bell`, мелодия по умолчанию.
- **Повтор, которого Chrono не умеет** (раз в месяц, каждые 2 недели, `COUNT`, `UNTIL`…) — *мой выбор*: импортируется как разовая запись на ближайшее повторение и обновляется при каждой синхронизации; обратно в Google такое событие не перезаписывается, пока пользователь не изменил запись в Chrono.
- **Событие на весь день** — *мой выбор*: запись на 00:00 без оповещения (`None`), видна в ленте.
- **Пояс времени**: при импорте время события переводится в местное «настенное» время телефона — как хранится `At`.
- **Прошедшие события** — *мой выбор*: остаются только в Google как история и в Chrono не загружаются. Загружаются разовые события, чьё начало позже текущего момента, и повторы, у которых есть будущее повторение. Так запись по-прежнему идёт только через `AlarmService.Save` (правило «время в будущем» не ослабляется), а сработавшая «Один раз и удалить» не возвращается при полной загрузке (её событие в Google уже в прошлом). Событие, которое идёт прямо сейчас (начало прошло, конец впереди), тоже не загружается.

### 6.3 Синхронизация

- **Когда**: после входа (полная загрузка), при открытии приложения, через несколько секунд после каждой правки записи, при загрузке телефона (`BootReceiver`) и периодически в фоне (Android WorkManager, раз в ~15 мин — минимум системы; новая зависимость `Xamarin.AndroidX.Work.Runtime`, версию проверить по NuGet).
- **Как**: `events.list` по календарю «Chrono» с `syncToken` — только изменения с прошлого раза; при `410 Gone` — полная загрузка. Отправка локальных изменений — очередь «грязных» записей (создана / изменена / удалена вручную), отправляемая, когда есть сеть и токен.
- **Конфликт** (запись изменена и в Chrono, и в Google с прошлой синхронизации) — побеждает более позднее изменение (`updated` события против времени локальной правки). *мой выбор*
- **Удаление в Google** (`status: cancelled`) → запись удаляется в Chrono и снимается с расписания будильников.
- **После любой синхронизации** — `AlarmService.RescheduleAll`, чтобы звонки соответствовали данным.
- **Без входа и без сети** приложение работает полностью локально; ошибки синхронизации не мешают сохранению записей.

### 6.4 Звонок по напоминаниям Google

- У записи появляется список смещений напоминаний (минуты до начала), заполняется из `reminders` события Google (`overrides`; при `useDefault` — напоминания календаря «Chrono» по умолчанию).
- Каждое смещение — отдельный звонок того же уровня, что и сама запись, плюс звонок в момент начала (решение «оба раза»). Для `Notify` — уведомление, для `None` — ничего.
- Записи, созданные в Chrono, напоминаний в Google не получают (`reminders.useDefault = false`, пустые `overrides`) — у них свои звонки Chrono. *мой выбор*
- Это затрагивает планировщики (Android `AlarmScheduler`, `IosNotificationPlan` с лимитом 64 уведомлений iOS) — дополнительные звонки делят тот же лимит.

### 6.5 Интерфейс

- «Настройки»: группа «Google Календарь» — кнопка «Войти через Google» / строка «Аккаунт: …» с «Выйти», строка состояния («Синхронизировано в 14:05», «Нет сети», «Нужно войти снова» — `GoldInk`), кнопка «Синхронизировать сейчас». Вид — по `DESIGN.md` (группа строк, accent-кнопка).
- После первого входа на телефоне, где уже есть локальные записи: они отправляются в календарь «Chrono» (не теряются), события из Google — загружаются; дубли по `chronoId` не создаются.

### 6.6 Изменения одного повторения в Google

Если в Google изменить или удалить одно повторение серии («только это событие»), Chrono этого не отобразит — серия звонит по правилу. Отмечено как не-цель; *мой выбор*, потому что модель записи Chrono не хранит исключений серии.

## 7. Что решает исполнитель

- Имена типов и файлов, как разложить код синхронизации (с учётом правила «без лишних private-помощников»).
- Хранение `syncToken`, id календаря и очереди изменений (`Preferences` или файл рядом с `alarms.json`).
- Вызовы Calendar API — `HttpClient` напрямую или пакет `Google.Apis.Calendar.v3` (если совместим с net11-android и не раздувает сборку).
- Формат строк состояния, тексты кнопок (в обоих resx).
- Точный способ запуска периодической фоновой синхронизации на Android.
